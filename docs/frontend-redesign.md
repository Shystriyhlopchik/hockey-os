# Редизайн интерфейса ЧХЛ

Рабочий проект: `hockey-os`. Обновлены публичные страницы и кабинет организатора.

## Оформление

- Тёмный фон, графитовые карточки, красный акцент, прямые линии и крупные заголовки в духе предоставленного референса.
- Oswald для заголовков и счёта, Play для текста, форм и таблиц. Шрифты размещены в `frontend/public/fonts`, сторонние запросы для их загрузки не нужны. Файлы лицензий OFL находятся рядом.
- Логотип ЧХЛ сохранён. Команды представлены общим компонентом эмблемы с аббревиатурой и цветом команды; фотографии игроков заменены инициалами, пока в данных нет портретов.
- Ближайшие игры расположены сразу после шапки: единая последовательность матчей запущенных турниров без выбора сезона и лиги.
- Переключатель лиги в блоке статистики одновременно обновляет таблицу, результаты, показатели сезона и лидеров.
- Новостной блок использует реальные записи приложения. Хоккейное изображение помечено как иллюстрация. Названия арен получаются из календаря; схема катка — декоративная иллюстрация.
- На узких экранах карточки ближайших игр прокручиваются горизонтально. Таблицы и меню кабинета имеют собственную прокрутку; формы протокола и календаря перестраиваются по ширине экрана.
- Есть видимый фокус клавиатуры, ссылка пропуска меню, управление диалогами через Escape, удержание фокуса внутри диалога и возврат фокуса при закрытии. Переход из несохранённого протокола или календаря требует подтверждения.
- Для печати протокола используется отдельный белый бланк.

## Структура фронтенда

```text
frontend/src/
  app.ts, app.html              # каркас приложения и общие уведомления
  app.config.ts                # Router и HttpClient
  app.routes.ts                # ленивые маршруты страниц и защита несохранённых правок
  components/                  # повторно используемые элементы интерфейса
    site-header/, site-footer/
    match-card/, match-row/, team-badge/
    section-heading/, standings-table/, leader-board/
    protocol-sheet/, dialog-focus/
  core/
    api/                       # единая HTTP-граница
    models/                    # модели общих данных
    state/                     # сигналы, вычисляемые выборки, неизменяемые обновления
    routing/, format/
    analytics.ts
  features/
    home/, calendar/, tournaments/, teams/, players/
    matches/, news/, regulations/
    office/, protocol/, dialogs/, not-found/
```

Организация по функциям, одинаковые имена связанных файлов, `inject`, `protected` для привязок шаблона и `OnPush` соответствуют [официальному руководству Angular](https://angular.dev/style-guide). Общие компоненты вынесены в `components` по требованию проекта. Тесты чистых функций находятся рядом с реализацией в файлах `.spec.ts`.

Классы остались только там, где их требует Angular: компоненты и директива. Прикладная логика оформлена функциями без наследования и иерархий сервисов.

`LEAGUE_STATE` создаётся фабрикой `InjectionToken`: `signal` хранит данные, выбор и черновики; `computed` рассчитывает видимые списки и сводки. Редактирование использует новые объекты и массивы, чтобы изменения надёжно отслеживались сигналами. Шаблонные элементы форм связаны с сигналами через явные обработчики изменений.

RxJS используется для загрузки деталей маршрута, отмены устаревших запросов, проверки ФИО с задержкой 300 мс и уведомлений. Подписки завершаются через `takeUntilDestroyed`; HTTP-запросы выполняет `HttpClient`. Команды сохранения ожидают завершения запроса через `firstValueFrom`.

Динамические поля черновиков пока сохраняют совместимость с существующим API протокола. Серверная модель и схема БД не изменены, миграции для редизайна не нужны.

## Проверка изменений

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm --dir frontend format:check
pnpm test:integration
```

Интеграционные проверки требуют локальный PostgreSQL и переменные окружения из инструкции проекта. Они создают собственные временные базы. Для ручной проверки также использовалась отдельная временная БД, без подключения к боевому сайту.

Проверено при разработке:

- production-сборка фронтенда без предупреждений Angular;
- 33 серверных и 33 фронтенд-теста;
- 61 интеграционный сценарий: 5 проверок ФИО, 13 проверок удаления игрока и 43 сценария приложения;
- переключение лиги, защита от повторного ФИО и открытие существующей заявки;
- перенос матча между турами с сохранением;
- сохранение и восстановление черновика протокола: гол во втором периоде на 21:00, ассистент, пересчёт счёта и заполнение печатного бланка;
- отсутствие горизонтального переполнения главной, календаря и протокола при мобильной ширине 390 px; мобильное меню и редактор расписания;
- отсутствие ошибок и предупреждений в консоли проверенных страниц.

Счётчик Яндекс.Метрики `114207477` сохранён. В локальной тестовой сборке он временно отключался, чтобы просмотры при проверке не попадали в статистику; после проверки исходный production-файл восстановлен.
