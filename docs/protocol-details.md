# Дополнения к протоколу матча

## Для секретаря

- **Лучший игрок матча** выбирается над вкладками протокола. Можно выбрать одного участвовавшего хоккеиста любой команды, включая вратаря, либо оставить «Не выбран». Запасные без отметки участия недоступны. В режиме итогового счёта и при техническом результате награда не назначается; ранее выбранного игрока нужно снять вручную.
- Во вкладке **Голы** отдельно указываются **Составы при голе** и **Тип гола**. Например, «В большинстве» и «В пустые ворота» могут быть выбраны одновременно. Штрафной бросок не содержит ассистов и численного состава. Для старых голов в пустые ворота численный состав остаётся неизвестным до уточнения секретарём.
- Во вкладке **Удаления** заполняются **Начало удаления** и **Конец удаления**, накопленным временем от начала матча. Например, 21:15–23:15. Конец можно оставить пустым, если он не применим. Если момент назначения отличается от начала отбывания, откройте «Дополнительное время назначения» и включите соответствующий флажок. Тогда период относится к назначению, а отбывание может начаться в следующем периоде.
- MVP, ситуации голов, начало/конец удалений и заполненные должности судей отображаются в итоговом протоколе и XLSX. Фамилии хоккеистов в веб-просмотре ведут в их карточки. ФИО судей и представителей команд остаются текстом.
- Для опубликованного матча изменения сохраняются новой версией после указания причины исправления.

## Совместимость

Миграция структуры БД не требуется: новые поля хранятся в JSON черновиков и версий протокола. Старые документы не переписываются автоматически.

- `bestPlayerId` — необязательный ID MVP. Ссылка участвует в блокировках сохранения и проверке удаления игрока.
- `goals[].strength` — EV / PP / PP2 / SH / SH2 либо null, если состав неизвестен; `goalType` — regular / empty_net / penalty_shot. Прежний `situation` сохраняется согласованным с этими полями для совместимости со статистикой. Гол в пустые ворота не начисляется вратарю.
- `penalties[].timingMode` — start либо separate. В обычном режиме прежний `time` совпадает с `start`; в отдельном режиме `time` сохраняет момент назначения. `start` и `end` всегда содержат время от начала матча. Старое отдельное назначение не стирается при редактировании начала.
- Медицинские уведомления, как и раньше, доступны только в служебном протоколе и служебном XLSX.

## Проверки

`pnpm test` проверяет доменную логику, общие функции и функции frontend. `pnpm build` собирает обе части приложения.

`pnpm test:protocol` требует отдельный временный PostgreSQL на `127.0.0.1:15444` и переменную `PROTOCOL_TEST_DATABASE_URL`. Проверка создаёт собственную базу с префиксом `hockey_protocol_test_`, запускает сервер на порту 4124, проверяет черновик, публикацию, исправление и XLSX, затем удаляет тестовую базу. Рабочие env-файлы не используются: сервер запускается во временной папке с синтетическими настройками. Флаг `--preview` у скрипта оставляет тестовую копию запущенной до сигнала остановки.
