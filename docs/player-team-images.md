# Фотографии игроков и логотипы команд

## Использование

В кабинете откройте «Хоккеисты → Изменить» или редактор команды. Выберите «Загрузить изображение» / «Заменить изображение», проверьте предпросмотр и нажмите «Сохранить». Для удаления используйте «Удалить фотографию» / «Удалить логотип», затем сохраните карточку. Отмена не меняет сохранённое изображение.

Поддерживаются JPEG, PNG и WebP до 5 МБ, не менее 32×32 пикселей. Сервер проверяет и полностью декодирует файл, применяет ориентацию фотографии, убирает метаданные и уменьшает изображение. Фото ограничено размером 800×1000, логотип — 512×512; пропорции и прозрачность сохраняются. При отсутствии или недоступности файла используется стандартная заглушка.

У игрока одно фото во всех сезонах и лигах. Изменение изображения не меняет ID, заявки, результаты и личную статистику. Суперпользователь и администратор сообщества редактируют любые карточки. Администратор турнира и секретарь должны иметь доступ ко всем турнирам с действующими заявками игрока или участием команды. Карточки вне турниров редактируются глобальными администраторами. Удаление фото не удаляет саму карточку игрока.

Фотографии доступны в карточках, списках, составах и блоках лидеров, логотипы — в местах использования общей эмблемы команды, включая календарь и таблицы. Изображение применяется только при сохранении формы. Если изображение уже заменили в другом окне, устаревшее сохранение отклоняется.

## Обновление ВМ

Новая миграция `PlayerTeamMedia1795550400000` добавляет необязательные поля `players.photoUrl` и `teams.logoUrl`; она применяется при запуске приложения. Старые записи сохраняются с пустыми изображениями.

Перед обновлением выполните обычную резервную копию. Затем соберите и пересоздайте только сервис `app`. Файлы продолжают храниться в существующем Docker volume `news_uploads`, подключённом к `/app/uploads`; переименовывать или удалять том не нужно.

Nginx должен содержать `client_max_body_size 6m;` в конфигурации сайта. Шаблон `infrastructure/nginx/hockey.conf` уже содержит это значение. Для действующего сервера изменение конфигурации нужно проверить через `sudo nginx -t` и применить перезагрузкой Nginx.

После обновления проверьте загрузку, повторное открытие карточки, замену, удаление и отмену. Выбор файла сам по себе не отправляет его на сервер. Обновление изображения создаёт новый UUID-адрес, поэтому кэш браузера не мешает замене.

## Хранение и резервное копирование

Обложки новостей находятся в `/app/uploads/news`, фотографии — в `/app/uploads/players`, логотипы — в `/app/uploads/teams`. Пользовательское имя файла не используется. При ошибке сохранения новый файл удаляется; прежний файл удаляется только после успешного изменения записи в БД.

`scripts/backup-production.sh` сохраняет дамп БД и архив всего `/app/uploads`. На время копирования блокируются только изменения ссылок на фотографии и логотипы; чтение сайта и ввод протоколов продолжаются. Это сохраняет согласованность дампа и файлов при одновременной замене изображений. Первое резервное копирование перед обновлением совместимо с прежним образом приложения, ещё не имеющим фотографий.

Для полного восстановления нужны оба файла: `.dump` и `.uploads.tar.gz`. Архив содержит каталоги `news`, `players` и `teams` относительно корня `/app/uploads`. Старые архивы только с `news` также распаковываются в этот корень. Блокировка не ограничивает срок хранения резервных копий; копии следует переносить с ВМ обычным способом.

## Проверки разработчика

`pnpm test` проверяет обработку и валидацию изображений вместе с существующей логикой. `pnpm test:media` требует отдельный PostgreSQL на `127.0.0.1:15445` и переменную `MEDIA_TEST_DATABASE_URL`. Скрипт создаёт собственную БД, запускает приложение на порту 4134 во временной папке с тестовыми настройками, проверяет загрузку, права, удаление, гонки, откат сохранения, перезапуск и архив, затем очищает тестовые данные. Рабочие env-файлы не читаются. Для временной проверки интерфейса предусмотрен флаг `--preview`.
