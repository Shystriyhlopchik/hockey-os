# Хоккей города

Первая рабочая версия хоккейного приложения с одним сообществом и несколькими турнирами. Публичная часть показывает календарь, результаты, команды, игроков, статистику и сетку плей-офф. Служебный кабинет предназначен для организаторов и секретарей.

Стек: Angular 19, NestJS 11, TypeORM и настоящая PostgreSQL. Данные сохраняются в базе, а не в браузере. Исходный league-os в другой папке не изменяется. Из него использованы архитектурные решения и локальные шрифты с лицензиями OFL; хоккейная модель и интерфейс находятся в этом проекте.

## Развёртывание на общей ВМ

Пошаговая [инструкция для ВМ с «Лигой двора» и sport-cheb](docs/deployment-vm.md): отдельный Compose-проект `hockey-os-prod`, PostgreSQL без публикации порта и приложение на `127.0.0.1:8082` за существующим Nginx. Используйте `compose.production.yml` и `.env.production`; команды запуска приведены в инструкции. Файлы для сборки и настройки включены в проект. Полная проверка Linux-контейнеров выполняется на целевой ВМ.

## Локальный запуск целиком в Docker

Запустите Docker Desktop и из корня проекта выполните:

```powershell
docker compose -f compose.local.yml up -d --build --wait --wait-timeout 180
```

Открыть [локальный сайт](http://localhost:8082). Вход в кабинет: `admin` / `Hockey2026!`. Node.js и pnpm на компьютере для этого способа не нужны. Первая сборка может занять несколько минут.

`compose.local.yml` запускает и приложение, и PostgreSQL в отдельном проекте `hockey-os-local`. База не публикует свой порт, сайт доступен только локально на 8082. Тестовые данные хранятся в отдельном томе; production-конфигурация и существующие установки league-os / sport-cheb не используются. Предустановленные ключ и пароль предназначены для локальной демонстрации.

После изменения исходников повторите команду запуска с `--build`. Остановка с сохранением данных: `docker compose -f compose.local.yml stop`. Просмотр журнала: `docker compose -f compose.local.yml logs --tail 100 app`. Если порт 8082 занят, задайте `$env:HOCKEY_LOCAL_PORT="8083"` в PowerShell перед запуском и откройте `http://localhost:8083`.

## Быстрый запуск без контейнера приложения

Нужны Node.js 22.13+ и pnpm 11. Команды выполняются из корня этого проекта.

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm run setup
pnpm dev
```

Открыть [приложение в режиме разработки](http://localhost:4300).

`pnpm run setup` создаёт локальный `.env` с отдельным случайным ключом сессии, если файла ещё нет. Существующий `.env` сохраняется. `pnpm dev` проверяет базу, при необходимости запускает переносимую PostgreSQL, собирает backend и запускает API и Angular. Повторное создание демонстрационных записей при перезапуске не выполняется.

Для использования Docker вместо переносимой базы:

```powershell
pnpm run setup
pnpm db:up
pnpm dev
```

В этом варианте должен работать Docker Desktop. База публикует только локальный порт 55440. Уже используемые league-os порты 4000 и 4200 не затрагиваются.

## Собранное приложение

```powershell
pnpm build
pnpm start
```

При работающей PostgreSQL приложение целиком доступно на [localhost:4100](http://localhost:4100). NestJS обслуживает собранный Angular и API на одном адресе. Если база ещё не запущена, выполните `pnpm db:local` в отдельном терминале или `pnpm db:up` для Docker. Проверка API: [localhost:4100/api/health](http://localhost:4100/api/health).

## Демонстрационные пользователи

При `DEMO_SEED=true` первая установка создаёт следующие учётные записи. Общий локальный демонстрационный пароль — `Hockey2026!`, если вы не изменили `DEMO_PASSWORD` до первого запуска.

| Логин | Роль |
|---|---|
| `admin` | Суперпользователь |
| `community` | Администратор сообщества |
| `organizer` | Администратор двух демонстрационных турниров |
| `secretary` | Секретарь двух демонстрационных турниров |

Наполнение: одно сообщество, сезон 2026/2027, дивизионы 18+ и 40+, 16 команд, 352 вымышленных хоккеиста, 112 матчей календаря и 16 опубликованных протоколов. Названия, составы и новости редактируются в кабинете. Медицинские и страховые отметки в примере также вымышлены.

## Работа секретаря

1. Войти как `secretary`, открыть «Матчи и протоколы» и выбрать матч.
2. Во вкладке «Составы» выбрать участников. Поле «В заявке» и фактическое участие учитываются отдельно; запасной вратарь без выхода на лёд не получает сыгранный матч.
3. После игры внести голы с периодом, временем, автором и двумя ассистентами, удаления и интервалы вратарей. Время голов и удалений отсчитывается от начала матча: например, `21:00` во втором периоде и `42:00` в третьем. Интервалы вратарей также используют общее время, например `00:00–45:00`.
4. Сохранить черновик или опубликовать протокол. Черновик сохраняется на сервере и восстанавливается при повторном открытии. Публикация обновляет таблицу, статистику и результат серии.
5. Для изменения опубликованного протокола указать причину. Создаётся новая версия; прежние записи сохраняются. Одновременное редактирование обнаруживается по версиям, устаревшее сохранение отклоняется.

Режим «Только итоговый счёт» позволяет зарегистрировать результат без выдуманных голов и передач. В этом режиме индивидуальная статистика не начисляется. Технический результат 5:0 или 0:5 устанавливает администратор турнира с обязательным основанием. Он учитывается в матчах, победах/поражениях и очках; условные шайбы не включаются в командные показатели, личные встречи и общий счётчик шайб. Личная статистика не начисляется. Правило единое для всех турниров; обычные сыгранные 5:0 учитываются полностью.

Секретарь ведёт карточки игроков, сезонные заявки и составы назначенных турниров. Администратор турнира меняет его календарь и назначает существующих секретарей через «Турниры → Секретари». Пользователей и их роли создаёт администратор сообщества или суперпользователь. Самостоятельной регистрации команд и игроков нет.

## Турниры и плей-офф

Создать сезон и турнир можно в кабинете администратора. Выберите команды и профиль правил, сформируйте календарь, проверьте даты и запустите турнир. Команды создаются в общем каталоге; в начавшийся турнир новые команды не добавляются. Правила запущенного турнира зафиксированы.

Профиль первого фестиваля: 3×15 минут, два круга, ничьи в регулярке, два очка за победу и одно за ничью. Четвертьфинал и полуфинал — до двух побед, начальная настройка финала — до четырёх. Недостающие игровые параметры дополнены по согласованному ориентиру КХЛ. Настройки другого турнира могут отличаться; редактор предоставляет числовые лимиты и профиль стандартного хоккея.

После завершения всех матчей регулярки администратор запускает сетку на 2, 4 или 8 команд. Она фиксирует посев и создаёт серии. Победитель определяется числом побед, без суммирования шайб нескольких матчей. Ненужные игры завершённой серии отменяются, победители переходят дальше. Если результат пересмотрен и серия снова открыта, несыгранные матчи восстанавливаются. Начатая следующая серия защищена от изменения её участников.

После финала приложение показывает чемпиона, серебро и бронзу. Бронза присуждается лучшему по регулярному этапу из проигравших полуфиналистов. Если все поддержанные критерии таблицы совпали, автоматический запуск сетки останавливается и показывает необходимость решения организатора; отдельный интерфейс жеребьёвки ещё не добавлен.

## Экспорт и печать

У опубликованного матча доступны XLSX с листами «Протокол» и «Дополнения» и печатная публичная страница. «Печать / PDF» открывает печать браузера, где можно сохранить PDF. Экспорт содержит составы, участие, голы, два ассистента, удаления, вратарей, броски и замечания. Это собственная форма приложения по структуре предоставленного образца, без заявления об интеграции с реестром ФХР.

## Данные и остановка

Переносимая PostgreSQL хранит данные в `.local/postgres` текущего проекта. На Windows для поддержки кириллического пути создаётся временный ASCII-псевдоним, указывающий на эту же папку; сами записи остаются в проекте. Копия исполняемых файлов PostgreSQL находится в системной временной папке. Docker хранит данные в отдельном именованном томе `hockey-os_hockey_postgres`.

Серверы в терминале останавливаются через Ctrl+C. Если переносимая база продолжает работать, используйте `pnpm db:stop:local`. Для Docker — `pnpm db:stop`. Эти команды останавливают базу и сохраняют данные. `.env`, `.local` и зависимости не включаются в Git.

## Проверки

```powershell
pnpm test
pnpm test:integration
pnpm build
```

Сквозной сценарий использует отдельную базу с уникальным именем `hockey_test_*` на локальном PostgreSQL и API на порту 4101. Создаёт её сам и удаляет только её в конце. Рабочая `hockey_os` не очищается. Проверяются роли и назначения, закрытые поля, атомарная регистрация игрока, пересечения площадок, черновики, версии протокола, статистика, экспорт, пересмотр серии, продвижение в финал и присуждение бронзы.

## Границы этой версии

Онлайн-таймер и ведение событий по ходу матча отложены по решению пользователя. Также пока не реализованы импорт заполненных XLSX, загрузка фотографий и видео, отправка уведомлений, автоматические дисквалификации, ручная жеребьёвка при полном равенстве и административная перестройка уже начатой следующей серии.

Броски по воротам не учитываются, поэтому процент отражённых бросков не показывается. Составы на льду при каждом голе и «плюс/минус» не вводятся. Удаления сохраняются секретарём, автоматический расчёт всех сочетаний штрафов и численного состава относится к следующему этапу.

Это локальная версия для проверки рабочих процессов. Внешнее развёртывание не выполнялось. Перед размещением рабочей установки нужны собственные учётные записи и начальный пароль, `DEMO_SEED=false`, HTTPS, настроенный `FRONTEND_ORIGIN` и резервное копирование PostgreSQL. При первой production-установке приложение отказывается создавать демо-наполнение и использовать демонстрационный пароль.

Подробный продуктовый план находится в [документе проекта](docs/hockey-project-plan.md).

## Изменение готового календаря

Администратор может менять календарь после запуска турнира: «Матчи и протоколы → Редактировать календарь» или кнопка в карточке турнира. По умолчанию выбран ближайший тур; вариант «Все матчи турнира» позволяет сверить календарь целиком с бумажной версией. Для переноса игры между турами измените её поле «Тур» (целое число от 1 до 1000, включая новый номер). Дата, время и площадка меняются отдельно. До сохранения строка остаётся в исходной группе и показывает исходный и новый тур; так можно перенести все матчи даже из опустевшего тура. Для выбранной группы можно применить общую дату и площадку. Правки нескольких туров сохраняются вместе. Номера матчей, пары команд, составы и черновики протоколов сохраняются. Опубликованные матчи закрыты для редактирования, игры плей-офф сохраняют свою серию; при пересечении команд или площадок весь пакет отклоняется. Одновременное редактирование защищено проверкой исходного тура и расписания. Изменения записываются в журнал.

## Переключение лиг на главной

Блок «Лиги сезона» над таблицей переключает турнирную таблицу, последние четыре результата и четырёх лидеров по очкам на выбранную лигу. Выбор сохраняется в браузере и используется при переходе к подробной таблице и статистике. Лидеры на главной не зависят от фильтров страницы хоккеистов. «Ближайшие игры» продолжает показывать общий календарь всех запущенных турниров.

## Время событий в протоколе

Голы и удаления вводятся в формате ММ:СС от начала матча. Например, 2-й период — 21:00, 3-й период — 42:00 (допустимо как для 3×15, так и для 3×20). Диапазон зависит от правил турнира и показан рядом с полем: для 3×15 это 00:00–15:00, 15:00–30:00 и 30:00–45:00. Овертаймы продолжают общий отсчёт. Старые протоколы и черновики автоматически отображаются в общем времени, опубликованные версии в базе не переписываются. Публичная страница и XLSX используют тот же отсчёт. Новые протоколы передают `timeBasis: "match"`; отсутствие поля в старых данных означает время внутри периода. Интервалы вратарей и начало/окончание штрафов остаются во времени от начала матча.

## Один игрок в нескольких лигах

У хоккеиста одна общая карточка. Для участия во второй лиге выберите его в форме «Сезонная заявка», не создавая повторную карточку. Заявки и статистика разделяются по турниру и команде. В одном турнире допускается только одна действующая заявка игрока — ограничение защищено уникальным индексом БД. Администратор может оформить переход в пределах регламента: прежняя заявка становится неактивной, статистика сыгранных матчей сохраняется. Заявка и показатели в другой лиге при этом не меняются.


### Послематчевый протокол по бланку ФХР

В кабинете откройте «Матчи и протоколы» → «Заполнить». Восемь вкладок повторяют разделы бумажного бланка: матч, составы, голы, удаления, вратари / БП, судьи, замечания и проверка. Укажите номер с бумажного бланка (он не меняет внутренний ID), фактическое время в МСК, представителей команд и судейскую бригаду. В голах при необходимости отметьте до шести игроков каждой команды на льду. События и тайм-ауты вводятся в общем времени от начала матча. Забитый штрафной бросок вносится как гол с ситуацией ШБ, незабитый — отдельной попыткой во вкладке вратарей; в удалениях предусмотрено назначение ШБ без штрафных минут.

Сводка голов и штрафов по периодам рассчитывается автоматически. «Проверить бланк» показывает заполненный документ; «Печать / PDF» печатает текущую форму целиком, в том числе ещё не сохранённый черновик. Подписи ставятся на распечатке. Сохранение черновика и публикация используют прежние версии и защиту от одновременного редактирования. Старая структура протоколов поддерживается, миграция БД не нужна.

Уведомления врачей о травмах доступны только назначенным сотрудникам турнира через защищённые маршруты протокола и служебного XLSX. В публичном протоколе и публичном XLSX эти сведения исключаются. XLSX в кабинете содержит опубликованную версию; для печати текущих правок используйте вкладку проверки.


### Защита общей карточки игрока от дублей

ФИО проверяется по всему сообществу, включая другие турниры, прошлые сезоны и игроков без действующей заявки. Регистр, лишние пробелы, Unicode-представление букв и ё/е не создают нового человека. Другая дата рождения при том же ФИО не позволяет завести ещё одну карточку. Форма предлагает заявить существующего игрока в текущий турнир, сохраняя его ID и накопленную историю. Изменить ФИО существующей карточки на занятое также нельзя.

Проверка работает в интерфейсе, API и БД, в том числе при одновременных сохранениях. Миграция PlayerIdentity1794614400000 применяется при запуске приложения: резервирует уже существующие ФИО и устанавливает защиту новых записей. Имеющиеся дубли не удаляются и не объединяются автоматически; их IDs, заявки, черновики, опубликованные протоколы и статистика остаются на месте. Разрешено исправлять прочие данные прежнего дубля без смены ФИО. Объединение уже накопленной истории требует отдельной проверки.

### Удаление игрока суперпользователем

В кабинете «Хоккеисты» только суперпользователю доступна кнопка «Удалить». Фильтр «Вся система» показывает карточки всех лиг и сезонов; «Без действующей заявки» позволяет найти карточки, исключённые из составов. По умолчанию список по-прежнему относится только к выбранному турниру.

Перед удалением приложение показывает ФИО, ID и все сезонные заявки. Удаляется общая карточка вместе с действующими и архивными заявками; требуется отдельное подтверждение. Если игрок упоминается в любом сохранённом черновике, любой версии опубликованного протокола или в действующей зафиксированной заявке, удаление блокируется. Окно показывает связанные матчи. Такая защита сохраняет статистику и возможность пересмотра старых протоколов. Ошибочную заявку можно исключить через «Команды и составы»; объединение дублей с накопленной историей остаётся отдельной операцией.

Сервер повторно проверяет права, связи и актуальность карточки в транзакции. Сохранение протокола и заявки синхронизировано с удалением блокировкой игрока. Удаление записывается в журнал; защита ФИО освобождает имя только после удаления последней карточки. Новая миграция для этой возможности не требуется.

## Интерфейс и структура фронтенда

## Удобство ввода протокола

Вратари показываются первыми, затем полевые игроки; внутри каждой группы — номера по возрастанию. Новые голы появляются сверху, а в публичном протоколе и выгрузке события идут по игровому времени. [Подробности, единое правило технических результатов и скриншоты](docs/protocol-workflow.md).

### Партнёры на главной

Блок «Команда за командой» расположен между новостями и статистикой. Тексты, порядок, факты и ссылки задаются в `frontend/src/features/home/home-partners.ts`; логотипы находятся в `frontend/public/partners/`. Компонент `frontend/src/components/partner-showcase/` переключает истории по нажатию, поддерживает клавиатуру и отключает анимацию при системной настройке уменьшения движения. Неизвестные ссылки не показываются.

Источники исторических фактов: [Ядринмолоко](https://yamilk.ru/) — начало истории в 1931 году; [Аграрная карта Национальной библиотеки Чувашии](https://www.nbchr.ru/agro/index.php?reg=%D0%92%D1%83%D1%80%D0%BD%D0%B0%D1%80%D1%81%D0%BA%D0%B8%D0%B9+%D1%80%D0%B0%D0%B9%D0%BE%D0%BD) — образование Вурнарского мясокомбината в 1957 году. Направления работы «Медиагид» и частота «Авторадио» взяты из предоставленных логотипов; описание SportUP — с [официального сайта](https://sportup.su/). Логотипы уменьшены для веба без изменения цветов, пропорций и содержания. Остальные формулировки — презентационные тексты, без утверждений о размере или конкретном виде поддержки. Изменения не требуют миграции БД.

### Статистика вратарей

Публичная страница статистики содержит разделы «Полевые игроки» и «Вратари». Для вратарей показываются фактические игры, время на льду, пропущенные шайбы и КН за 60 минут. В карточке одного игрока показатели разделены по турниру и команде. Неполные исторические сведения показываются как отсутствие данных, а не нулевые пропущенные; сумма известных голов отдельно возвращается API в `knownGoalsAgainst`, полнота — в `goalieTracked`, `goalieTrackedGames`, `goalieUntrackedGames`.

В протоколе откройте «Вратари / БП»: выберите «весь матч» рядом с нужным вратарём либо задайте непрерывную последовательность интервалов от 00:00 до финальной сирены, включая пустые ворота. Кнопка полного матча снимает отметку «Играл» у запасных вратарей и не заменяет существующие интервалы. Время — от начала матча. Для овертайма длительность определяется решающей шайбой, для серии буллитов учитывается время овертайма.

Пропущенные вычисляются по времени голов соперника. При голе ровно в секунду замены выберите пропустившего вратаря в записи гола. Пустые ворота не начисляются вратарю; их отметка в голе должна совпадать с интервалом. Забитый штрафной бросок во время матча учитывается, серия буллитов — отдельно. Технические результаты и режим одного итогового счёта личную статистику не создают.

Общий чистый расчёт находится в `shared/goalie-statistics.js` и используется сервером, формой, печатью и XLSX. Dockerfile включает этот каталог. Для публикаций из обновлённого интерфейса передаётся `goalieStatsVersion: 1`: сервер проверяет полноту интервалов и однозначность голов. Старые JSON-протоколы без этого поля сохраняют совместимость и пересчитываются при чтении; неполные сведения требуют дополнения секретарём. Миграция схемы БД не требуется.


### Новости сайта

Администратор сообщества и суперпользователь управляют новостями в «Кабинет → Новости».
Редактор позволяет сохранить черновик, загрузить обложку PNG/JPEG/WebP до 5 МБ, заполнить анонс и текст, посмотреть предпросмотр и опубликовать материал.
Адрес формируется из заголовка и фиксируется после первой публикации; старые ссылки /news/ID продолжают работать.
Снятие с публикации скрывает статью от посетителей. Удаление архивирует её, не освобождая ранее использованный адрес.
На главной показываются шесть последних опубликованных материалов; в архиве есть постраничная навигация.
Публикация в социальных сетях не подключается.

Миграция NewsEditorial запускается при старте приложения и сохраняет существующие статьи, категории и текст.
Обложки хранятся отдельно от образа в Docker volume news_uploads, смонтированном в /app/uploads (production и compose.local.yml).
При запуске без Docker используется UPLOAD_DIR или каталог uploads в рабочей директории.

При обновлении ВМ необходимо пересоздать сервис app через scripts/production.sh up -d --no-deps --no-build --wait app, чтобы подключился новый volume.
Для загрузки обложек в действующем Nginx-конфиге chhl.ru установите client_max_body_size 6m, проверьте nginx -t и перезагрузите конфигурацию Nginx.
Обновление шаблона infrastructure/nginx/hockey.conf само по себе не изменяет установленный конфиг и сертификат HTTPS.
Скрипт scripts/backup-production.sh сохраняет БД и отдельный архив всего хранилища: обложки, фотографии игроков и логотипы команд. Оба файла нужны для полного восстановления сайта.


Проверка редактора: pnpm test:news. Для сценария требуется отдельный локальный PostgreSQL на порту 55443 и переменная NEWS_TEST_DATABASE_URL.
Сценарий создаёт собственную временную БД, проверяет обновление старой схемы, права, загрузку изображений и публикацию, затем удаляет только свои тестовые данные.
