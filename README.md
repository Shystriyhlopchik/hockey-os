# Хоккей города

Первая рабочая версия хоккейного приложения с одним сообществом и несколькими турнирами. Публичная часть показывает календарь, результаты, команды, игроков, статистику и сетку плей-офф. Служебный кабинет предназначен для организаторов и секретарей.

Стек: Angular 19, NestJS 11, TypeORM и настоящая PostgreSQL. Данные сохраняются в базе, а не в браузере. Исходный league-os в другой папке не изменяется. Из него использованы архитектурные решения и локальные шрифты с лицензиями OFL; хоккейная модель и интерфейс находятся в этом проекте.

## Развёртывание на общей ВМ

Пошаговая [инструкция для ВМ с «Лигой двора» и sport-cheb](docs/deployment-vm.md): отдельный Compose-проект `hockey-os-prod`, PostgreSQL без публикации порта и приложение на `127.0.0.1:8082` за существующим Nginx. Используйте `compose.production.yml` и `.env.production`; команды запуска приведены в инструкции. Файлы для сборки и настройки включены в проект. Полная проверка Linux-контейнеров выполняется на целевой ВМ.

## Быстрый запуск

Нужны Node.js 22.13+ и pnpm 11. Команды выполняются из корня этого проекта.

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm setup
pnpm dev
```

Открыть [приложение в режиме разработки](http://localhost:4300).

`pnpm setup` создаёт локальный `.env` с отдельным случайным ключом сессии, если файла ещё нет. Существующий `.env` сохраняется. `pnpm dev` проверяет базу, при необходимости запускает переносимую PostgreSQL, собирает backend и запускает API и Angular. Повторное создание демонстрационных записей при перезапуске не выполняется.

Для использования Docker вместо переносимой базы:

```powershell
pnpm setup
pnpm db:up
pnpm dev
```

В этом варианте должен работать Docker Desktop. База публикует только локальный порт 55440. Уже используемые league-os порты 4000 и 4200 не затрагиваются.

## Собранное приложение

```powershell
pnpm build
pnpm start
```

При работающей PostgreSQL приложение целиком доступно на [localhost:4100](http://localhost:4100). NestJS обслуживает собранный Angular и API на одном адресе. Если база ещё не запущена, выполните `pnpm db:local` в отдельном терминале или `pnpm db:up` для Docker. Проверка API: [localhost:4100/api/health](http://localhost:4100/api/health).

## Демонстрационные пользователи

При `DEMO_SEED=true` первая установка создаёт следующие учётные записи. Общий локальный демонстрационный пароль — `Hockey2026!`, если вы не изменили `DEMO_PASSWORD` до первого запуска.

| Логин | Роль |
|---|---|
| `admin` | Суперпользователь |
| `community` | Администратор сообщества |
| `organizer` | Администратор двух демонстрационных турниров |
| `secretary` | Секретарь двух демонстрационных турниров |

Наполнение: одно сообщество, сезон 2026/2027, дивизионы 18+ и 40+, 16 команд, 352 вымышленных хоккеиста, 112 матчей календаря и 16 опубликованных протоколов. Названия, составы и новости редактируются в кабинете. Медицинские и страховые отметки в примере также вымышлены.

## Работа секретаря

1. Войти как `secretary`, открыть «Матчи и протоколы» и выбрать матч.
2. Во вкладке «Составы» выбрать участников. Поле «В заявке» и фактическое участие учитываются отдельно; запасной вратарь без выхода на лёд не получает сыгранный матч.
3. После игры внести голы с периодом, временем, автором и двумя ассистентами, удаления и интервалы вратарей. Время события отсчитывается от начала периода, например `04:35`; интервалы вратарей используют накопленное время, например `00:00–45:00`.
4. Сохранить черновик или опубликовать протокол. Черновик сохраняется на сервере и восстанавливается при повторном открытии. Публикация обновляет таблицу, статистику и результат серии.
5. Для изменения опубликованного протокола указать причину. Создаётся новая версия; прежние записи сохраняются. Одновременное редактирование обнаруживается по версиям, устаревшее сохранение отклоняется.

Режим «Только итоговый счёт» позволяет зарегистрировать результат без выдуманных голов и передач. В этом режиме индивидуальная статистика не начисляется. Технический результат 5:0 или 0:5 устанавливает администратор турнира с обязательным основанием.

Секретарь ведёт карточки игроков, сезонные заявки и составы назначенных турниров. Администратор турнира меняет его календарь и назначает существующих секретарей через «Турниры → Секретари». Пользователей и их роли создаёт администратор сообщества или суперпользователь. Самостоятельной регистрации команд и игроков нет.

## Турниры и плей-офф

Создать сезон и турнир можно в кабинете администратора. Выберите команды и профиль правил, сформируйте календарь, проверьте даты и запустите турнир. Команды создаются в общем каталоге; в начавшийся турнир новые команды не добавляются. Правила запущенного турнира зафиксированы.

Профиль первого фестиваля: 3×15 минут, два круга, ничьи в регулярке, два очка за победу и одно за ничью. Четвертьфинал и полуфинал — до двух побед, начальная настройка финала — до четырёх. Недостающие игровые параметры дополнены по согласованному ориентиру КХЛ. Настройки другого турнира могут отличаться; редактор предоставляет числовые лимиты и профиль стандартного хоккея.

После завершения всех матчей регулярки администратор запускает сетку на 2, 4 или 8 команд. Она фиксирует посев и создаёт серии. Победитель определяется числом побед, без суммирования шайб нескольких матчей. Ненужные игры завершённой серии отменяются, победители переходят дальше. Если результат пересмотрен и серия снова открыта, несыгранные матчи восстанавливаются. Начатая следующая серия защищена от изменения её участников.

После финала приложение показывает чемпиона, серебро и бронзу. Бронза присуждается лучшему по регулярному этапу из проигравших полуфиналистов. Если все поддержанные критерии таблицы совпали, автоматический запуск сетки останавливается и показывает необходимость решения организатора; отдельный интерфейс жеребьёвки ещё не добавлен.

## Экспорт и печать

У опубликованного матча доступны XLSX с листами «Протокол» и «Дополнения» и печатная публичная страница. «Печать / PDF» открывает печать браузера, где можно сохранить PDF. Экспорт содержит составы, участие, голы, два ассистента, удаления, вратарей, броски и замечания. Это собственная форма приложения по структуре предоставленного образца, без заявления об интеграции с реестром ФХР.

## Данные и остановка

Переносимая PostgreSQL хранит данные в `.local/postgres` текущего проекта. На Windows для поддержки кириллического пути создаётся временный ASCII-псевдоним, указывающий на эту же папку; сами записи остаются в проекте. Копия исполняемых файлов PostgreSQL находится в системной временной папке. Docker хранит данные в отдельном именованном томе `hockey-os_hockey_postgres`.

Серверы в терминале останавливаются через Ctrl+C. Если переносимая база продолжает работать, используйте `pnpm db:stop:local`. Для Docker — `pnpm db:stop`. Эти команды останавливают базу и сохраняют данные. `.env`, `.local` и зависимости не включаются в Git.

## Проверки

```powershell
pnpm test
pnpm test:integration
pnpm build
```

Сквозной сценарий использует отдельную базу с уникальным именем `hockey_test_*` на локальном PostgreSQL и API на порту 4101. Создаёт её сам и удаляет только её в конце. Рабочая `hockey_os` не очищается. Проверяются роли и назначения, закрытые поля, атомарная регистрация игрока, пересечения площадок, черновики, версии протокола, статистика, экспорт, пересмотр серии, продвижение в финал и присуждение бронзы.

## Границы этой версии

Онлайн-таймер и ведение событий по ходу матча отложены по решению пользователя. Также пока не реализованы импорт заполненных XLSX, загрузка фотографий и видео, отправка уведомлений, автоматические дисквалификации, ручная жеребьёвка при полном равенстве и административная перестройка уже начатой следующей серии.

Броски по воротам не учитываются, поэтому процент отражённых бросков не показывается. Составы на льду при каждом голе и «плюс/минус» не вводятся. Удаления сохраняются секретарём, автоматический расчёт всех сочетаний штрафов и численного состава относится к следующему этапу.

Это локальная версия для проверки рабочих процессов. Внешнее развёртывание не выполнялось. Перед размещением рабочей установки нужны собственные учётные записи и начальный пароль, `DEMO_SEED=false`, HTTPS, настроенный `FRONTEND_ORIGIN` и резервное копирование PostgreSQL. При первой production-установке приложение отказывается создавать демо-наполнение и использовать демонстрационный пароль.

Подробный продуктовый план находится в [документе проекта](docs/hockey-project-plan.md).

## Изменение готового календаря

Администратор может менять календарь после запуска турнира: «Матчи и протоколы → Редактировать календарь» или кнопка в карточке турнира. По умолчанию выбран ближайший тур; вариант «Все матчи турнира» позволяет сверить календарь целиком с бумажной версией. Для переноса игры между турами измените её поле «Тур» (целое число от 1 до 1000, включая новый номер). Дата, время и площадка меняются отдельно. До сохранения строка остаётся в исходной группе и показывает исходный и новый тур; так можно перенести все матчи даже из опустевшего тура. Для выбранной группы можно применить общую дату и площадку. Правки нескольких туров сохраняются вместе. Номера матчей, пары команд, составы и черновики протоколов сохраняются. Опубликованные матчи закрыты для редактирования, игры плей-офф сохраняют свою серию; при пересечении команд или площадок весь пакет отклоняется. Одновременное редактирование защищено проверкой исходного тура и расписания. Изменения записываются в журнал.
